# Connectivity matrix

Environment: **Atom** (personal, limited network). 12 exact hosts allowlisted, no wildcards,
no credentials or secrets stored. Package registries and MCP-server hosts are also allowed.
Generated by `python -m atomtrader.diagnostics.connectivity`. Re-run any time; it exits
non-zero if any check deviates from its expectation.

**Failure taxonomy** (from `atomtrader/marketdata/http.py`): `proxy_blocked` = egress policy;
`network_error` = DNS/TLS/timeout; `rate_limited` = 429; `server_error` = 5xx;
`api_rejection` = request- or token-specific 4xx (the endpoint is up); `invalid_response` =
2xx with an unexpected body. Only network/429/5xx are retried.

### Corrections made during verification
- My first Jupiter/RugCheck "failures" used a **wrong USDC mint typed from memory**.
  Both APIs correctly rejected it. The verified mint is
  `EPjFWdd5AufqSSqeM2qN1xzybapC8G4wEGGkZwyTDt1v`. Reference tokens are now resolved
  at runtime from provider token lists, never hard-coded from memory.
- Jupiter's search also returns an **impostor "USDC"** (unverified, $4k liquidity) — tokens
  are identified by mint/contract + verification status, never by symbol.
- Frankfurter v1 is deprecated; the bot uses `/v2/providers/ecb/rates`.
